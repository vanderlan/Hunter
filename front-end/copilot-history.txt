### BACKEND API ENDPOINTS AVAILABLE
1. **Authentication**
   - POST /api/auth/login - User login (returns JWT + refresh token)
   - POST /api/auth/refresh-token - Refresh JWT token

2. **Jobs**
   - GET /api/jobs/active - Get all active job positions
   - GET /api/jobs/active?companyCode={code} - Filter by company
   - POST /api/jobs/sync - Sync jobs from external source (Taller careers)

3. **Candidates**
   - POST /api/candidates/analyze-cv - Upload PDF and analyze against jobs
     - Requires: multipart/form-data with PDF file (max 10MB)
     - Returns: Match percentages, matching skills, missing skills, job details

**Services Created:**

1. **AuthService** (`src/app/services/auth.service.ts`)
   - Purpose: Handle JWT authentication and token management
   - Key Features:
     - Login with email/password
     - Store JWT token and refresh token in localStorage
     - Auto-refresh token on expiration
     - Token expiration checking (every 60 seconds)
     - BehaviorSubject for authentication state
     - Automatic logout on token expiry
   - Methods:
     - `login(credentials)` - Authenticate user
     - `refreshToken()` - Get new JWT using refresh token
     - `logout()` - Clear tokens and redirect to login
     - `getToken()` - Retrieve stored JWT
     - `isAuthenticated()` - Check if user is logged in

2. **JobService** (`src/app/services/job.service.ts`)
   - Purpose: Handle job-related API calls
   - Key Features:
     - CV analysis with file upload
     - Fetch active job positions
     - Sync jobs from external source
     - Automatic API version header injection
   - Methods:
     - `analyzeCv(file: File)` - Upload PDF and get matches
     - `getActiveJobs(companyCode?)` - List job positions
     - `syncJobs()` - Trigger job synchronization

**Interceptors & Guards:**

1. **AuthInterceptor** (`src/app/interceptors/auth.interceptor.ts`)
   - Purpose: Automatically inject JWT token and handle 401 errors
   - Features:
     - Adds Authorization header with Bearer token to all requests
     - Intercepts 401 Unauthorized responses
     - Automatically calls refresh-token endpoint
     - Retries failed request with new token
     - Logs out user if refresh fails
     - Prevents infinite refresh loops

2. **AuthGuard** (`src/app/guards/auth.guard.ts`)
   - Purpose: Protect routes from unauthorized access
   - Features:
     - Checks if user is authenticated before route activation
     - Redirects to login page if not authenticated
     - Preserves return URL for post-login redirect

#### Phase 7: User Flow

**Authentication Flow:**
1. User visits app
2. AuthGuard checks authentication
3. If not authenticated → Redirect to /login
4. User enters credentials (adm@hunter.com / 123)
5. AuthService calls POST /api/auth/login
6. Backend returns JWT + refresh token
7. Tokens stored in localStorage
8. User redirected to home page (CV Analyzer)
9. All subsequent requests include JWT in Authorization header

**Token Refresh Flow:**
1. API request made with JWT
2. Backend returns 401 Unauthorized
3. AuthInterceptor catches error
4. Calls POST /api/auth/refresh-token with stored refresh token
5. Backend returns new JWT + refresh token
6. Tokens updated in localStorage
7. Original request retried with new token
8. If refresh fails → User logged out

**CV Analysis Flow:**
1. User at home page (CV Analyzer)
2. Drags PDF file or clicks browse
3. File validated (type: PDF, size: max 10MB)
4. File preview shown
5. User clicks "Analyze CV"
6. FormData created with file
7. POST request to /api/candidates/analyze-cv
8. Loading spinner shown (15-30 seconds)
9. Backend:
   - Extracts text from PDF
   - Fetches all active job positions
   - Sends CV + jobs to OpenAI GPT-4o
   - Receives structured JSON response
   - Filters matches > 20%
   - Sorts by match percentage descending
10. Frontend receives response
11. Match cards displayed in grid
12. User can:
    - Expand job details
    - View matching/missing skills
    - Click external job links
    - Upload another CV
