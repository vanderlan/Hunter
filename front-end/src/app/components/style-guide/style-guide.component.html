Hunter Design Language

Every value below is read live from styles/_tokens.scss. Build new screens from these tokens — never from raw hex.

Surfaces

A tonal ramp. Each step is an elevation plane, not a flat grey.

@for (s of surfaces; track s.token) {
{{ s.name }} {{ s.token }}
}

Brand

@for (s of brand; track s.token) {
{{ s.name }} {{ s.token }}
}
brand-tint --hunter-brand-tint

The accent is spent sparingly — active nav item, primary action, focus ring, selection. Chrome stays near-colourless so data carries the colour. There are no gradients in this system.

Status palette

Chips, badges, callouts and toasts all draw from these. One meaning, one colour, everywhere.

@for (tone of statuses; track tone) {
{{ tone }} --hunter-{{ tone }}-*
}

Badges

Hiring pipeline scale

The eight stages read as a cool → warm journey, so stage is legible from colour alone. Red appears exactly once, at the terminal Reproved state — which is why the brand is not red.

@for (st of stages; track st.key) { {{ st.label }} }

These classes come from HIRING_PROCESS_STATUS_CONFIG.cssClass, so every screen rendering a stage picks them up automatically.

Data visualisation

Categorical series

Distinct in hue and luminance, so they survive greyscale and the common colour-vision deficiencies.

@for (n of vizSeries; track n) {
viz-{{ n }}
}

Match score scale

Sequential, 0–100%. Low scores are muted rather than red: a weak match is not an error.

@for (st of scoreStops; track st) {
{{ st }}%
}

Density

Material runs at density -2 and the base size is 14px. This is a data tool; rows should be scannable, not comfortable.

{{ d.label }}
}
